使用与部署说明

一套代码，四种形态：网页、Windows 客户端、安卓 APK、iOS。本手册覆盖本地畅玩、局域网开房、公网部署上线、服务器控制台、MySQL 落库、客户端连接与规则速查。

1+.1 怎么用（三步）

  1. 把 TMH-谁是队友服务器-Windows服务端.zip 拷到服务器，右键 → 全部解压缩。注意 exe、runtime、server、web 必须在同一个文件夹里，少一个都起不来。
  2. 双击 TMH-谁是队友服务器.exe，弹出服务器窗口。
  3. 点「▶ 启动服务器」，等状态灯变绿「运行中」；把「局域网访问」那一行地址发给同桌的人（例如 http://192.168.1.10:8080），手机 / 电脑浏览器打开即可开局。关服点「■ 停止服务器」，或直接关窗口（关窗会自动停服并释放端口）。
提示：第一次启动时 Windows 可能弹出防火墙提示，选「允许访问」，否则别的设备连不进来。端口被占用时日志里会写红字原因，换个端口再点启动即可。

1+.2 为什么这样更稳（Win7 / Server 2012 R2 也能开）

旧版的服务器窗口是 Electron（Chromium 内核）做的，而 Electron 从 23 版起不再支持 Windows 7 / 8 / 8.1 内核；Windows Server 2012 R2 的内核正是 8.1，所以老系统上双击会弹「此应用无法在你的电脑上运行」。

现在这个窗口是原生 Win32 程序（Go 编译，约 5MB），完全不加载 Chromium；真正干活的是随包的 Node 18.20.8（位于 runtime\node.exe，最后一个官方支持 Win8.1 / Server 2012 R2 的 LTS），以隐藏窗口方式在后台跑，日志通过管道回传到界面里。所以：

  • 打开就是图形界面，没有任何黑框；
  • Windows 7 SP1 / 8 / 8.1 / 10 / 11，Server 2008 R2 / 2012 / 2012 R2 / 2016 / 2019 / 2022 都能用；
  • 绿色免安装，不写注册表、不装服务、不依赖 .NET / VC++ 运行库；
  • 功能与之前完全一致：开房、联机、记牌、MySQL 落库、网页控制台、1Mbps 外网优化。

文件什么时候用

1+.4 这个系统上的玩家怎么进游戏

服务器只是发布网页，玩家用浏览器进入即可；如果那台机器是 Win7 / 2012 R2，就不要在它上面用 Electron 客户端 exe（跑不起来，只开服也用不到）：

玩家怎么进
手机 / 平板连同一个 Wi-Fi，浏览器打开 http://服务器IP:8080；安卓用 Chrome，iPhone 用 Safari
Windows 10/11 电脑直接浏览器打开；也可以继续用 TMH-谁是队友.exe 客户端（Win10+ 正常）
老系统电脑（Win7/2012 R2）浏览器打开即可。这些机器自带 IE11，建议先装 Chrome / Edge / 火狐，游戏页面需要现代浏览器；只开服不用看页面的机器装不装都行
开服的那台机器自己窗口里点「打开游戏页面」，或浏览器打开 http://127.0.0.1:8080

1+.5 长期开服建议

  • 开机自启：把 TMH-谁是队友服务器.exe 的快捷方式放进「启动」文件夹（Win+R → shell:startup），配合「启动后自动打开游戏页面」不勾选，开机就在后台待命。
  • 看日志：窗口下方「运行日志」是实时的；远程排错也可以用网页控制台 /admin 的日志区。
  • 端口：默认 8080。若同机还跑着 IIS / 其它服务，改成 8081 之类，然后点「保存并重启服务器」。
  • MySQL：不装也能玩（内存模式，重启即清空战绩）；要长期保留对局就装 MySQL 8.0，在窗口里填地址账号后保存。
  • 不要用 Windows 自带的「服务」面板去托管：node.exe 不是服务程序，硬塞会被 1053 错误拒绝。
同样不能只拷单个文件：服务端是「一个文件夹」，TMH-谁是队友服务器.exe、runtime\node.exe、server\、web\ 缺一不可。换机器请拷整个 zip，或把整个文件夹一起拷走。

2本地畅玩

2.1 最省事：双击 Windows 客户端

  1. 把 发布/TMH-谁是队友/ 整个文件夹放到硬盘上（路径别太深也行）。
  2. 双击 TMH-谁是队友.exe。它会自动在 8080 端口启动内置服务器，并打开游戏窗口。
  3. 主菜单选「单人练习」直接和 3 个电脑打；或选「联机对战 → 创建房间」，把房间码给朋友。
  4. 朋友和你在同一 Wi-Fi 时，用手机浏览器打开菜单「联机 → 显示局域网地址」里的 http://192.168.x.x:8080 即可加入。
端口说明：如果 8080 已被别的程序占用，客户端会自动改用 8081、8082……并在窗口菜单「联机 → 显示局域网地址」里显示实际使用的端口；如果占用 8080 的正是本游戏的服务器（比如你先开了服务器控制台），客户端会直接复用它，不会报错。

2.2 网页版（免安装）

电脑上装了 Node.js 18+ 时：

  1. 双击根目录的 启动服务器.bat。它会另开一个窗口运行服务器，并自动打开 http://127.0.0.1:8080/。
  2. 不想用脚本就手动执行：在项目根目录打开命令行，运行 node server/index.js，然后浏览器访问 http://127.0.0.1:8080/。
  3. 停止服务：关掉那个黑色命令行窗口，或按 Ctrl+C。

换端口：node server/index.js --port 9000，或改 server/config.json 里的 port。

2.3 单人练习（完全离线）

不启动服务器也能玩：直接双击项目根目录的 index.html，或打开 exe / APP 后点「单人练习」。你坐 0 号位，另外 3 家是电脑，规则与联机完全一致。

2.4 网页进入：手机扫码就能玩（推荐给 iPhone）

网页版和 exe / 安卓 APP 是同一套代码、同一个服务器，不用安装、不用应用商店审核，iPhone、iPad、安卓、电脑都能进。

  1. 主菜单点「网页进入 · 手机扫码」，弹出二维码和网址。
  2. 手机相机或微信「扫一扫」扫描二维码，浏览器打开即进入游戏。
  3. 想直接进某个房间：在房间里点「扫码进房」，二维码里已经带好房间码，扫开就自动入座。
  4. 把它变成桌面图标：
    iPhone：Safari 打开 → 底部「分享」→「添加到主屏幕」，之后点图标全屏启动，和 App 一样没有地址栏。
    安卓：Chrome 右上角菜单 →「添加到主屏幕 / 安装应用」。
桌面客户端也能扫码：菜单栏「联机 → 网页进入（手机扫码）」。客户端窗口跑在 127.0.0.1 上，程序会自动向服务器查询本机局域网 IP，把二维码换成 http://192.168.x.x:8080，手机扫码即可加入，不需要手输地址。
二维码由本地脚本生成（js/qr.js，不依赖任何外网 CDN），断网的局域网环境同样可用；地址过长时会提示直接复制网址。

3同一 Wi-Fi 联机（最常用）

适用：家里、宿舍、办公室，4 个人连同一个路由器。延迟极低，不花流量。

第 1 步：找一台电脑当服务器

双击 TMH-谁是队友服务器.exe，出现控制台窗口，顶部状态变为「运行中」即成功。打开即自动起服，无需再点按钮。

第 2 步：拿到局域网地址

控制台「服务控制」卡片里会列出形如 http://192.168.3.24:8080 的地址（可能有多条，任选一条；手机能连上的那条通常和电脑同一网段）。也可以点「在浏览器打开」先在本机验证。

第 3 步：手机 / 其他电脑进入

手机连同一个 Wi-Fi，用浏览器（Safari / Chrome / 微信内置浏览器都行）打开上面的地址。安卓用户也可以装 APK，在设置里填这个地址。

第 4 步：开房

房主点「联机对战 → 创建房间」，得到 4 位房间码。其他人点「联机对战 → 加入房间」输码，或直接打开房主复制的邀请链接自动进房。

第 5 步：开局

4 个座位坐满后房主点「开始游戏」。人不够也没关系：空位会自动由电脑玩家补齐，随时能开局。

手机打不开页面？90% 是防火墙。第一次运行服务器时 Windows 会弹「是否允许访问网络」，必须勾选专用网络并允许。若当时点了取消，用管理员身份打开 PowerShell 执行下面这条命令补放行： 
netsh advfirewall firewall add rule name="TMH Poker 8080" dir=in action=allow protocol=TCP localport=8080
另外确认：手机和电脑在同一 Wi-Fi（不是手机流量）、路由器没开「AP 隔离 / 访客网络」、地址用的是 192.168.x.x 而不是 127.0.0.1。

4用服务器开房：房间逻辑说明

4.1 三种进房方式

方式 说明
创建房间 生成 4 位房间码（如 K7QM），你成为房主。房主负责点「开始游戏」，中途退出房间会解散。
加入房间 输入朋友给的房间码。房间码不区分大小写，只在本局服务器进程存活期间有效。
快速匹配 自动坐进第一个「还没开始且有空位」的房间；没有这样的房间就新建一个并把你设为房主。

4.2 邀请链接

房间界面点「复制邀请链接」，得到形如：

http://192.168.3.24:8080/?server=http%3A%2F%2F192.168.3.24%3A8080&room=K7QM

好友点开（或粘到浏览器）会自动连服务器并直接进房，不用手输房间码。公网部署时把地址换成你的域名即可，例如 https://poker.example.com/?server=https://poker.example.com&room=K7QM。

4.3 座位、电脑与断线

  • 一桌固定 4 个座位；空位在开局时由电脑玩家接管（界面标「电脑」）。
  • 服务器是权威端：发牌、判牌、电脑思考都在服务器上算，客户端只负责显示和上报操作，改前端代码无法作弊。
  • 真人掉线后，他的座位会由电脑接管继续打，不影响其他人；重进房间即恢复。
  • 所有人都离开后房间自动销毁；服务器重启，所有房间清空（战绩若配置了 MySQL 则会保留）。
关于「邀请好友（直连）」：主菜单里还有一个 P2P 模式，用公共信令 + 房间码点对点连接，不需要服务器，适合临时玩一局。它依赖外网 CDN（unpkg），完全断网时不可用；稳定开黑仍建议用服务器模式。

5公网部署上线

让外地朋友也能玩，需要一台公网可达的机器。下面三种方案按推荐程度排列。

5.1 方案 A：云服务器（最稳，推荐）

随便一台 1 核 1G 的 Linux 云主机就够（阿里云/腾讯云/华为云轻量应用服务器均可）。

① 上传文件

只需两类文件：服务器代码和前端页面。目录保持这样的结构（服务器的自动查找规则就认这个）：

/opt/tmh/
├─ server/          ← 项目里的 server/ 整个目录（含 node_modules）
└─ web/             ← 项目里的 dist/ 内容（index.html、css/、js/）

可用 scp、宝塔面板、WinSCP 上传。然后在服务器上装依赖（若已带 node_modules 可跳过）：

cd /opt/tmh/server
npm install --omit=dev

② 试运行

cd /opt/tmh/server
node index.js
# 看到「服务器已启动（端口 8080）」即成功，Ctrl+C 先停掉

③ 交给 systemd 常驻（推荐）

sudo nano /etc/systemd/system/tmh.service
[Unit]
Description=TMH Poker Server
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/tmh/server
ExecStart=/usr/bin/node index.js
Restart=always
RestartSec=3
User=www-data

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now tmh
sudo systemctl status tmh      # 查看状态
journalctl -u tmh -f           # 看实时日志

④ 放行端口

云厂商控制台的安全组里放行 TCP 8080（若走 Nginx，则只放行 80/443）。Linux 自带防火墙也要放行：

sudo ufw allow 8080/tcp        # Ubuntu/Debian
sudo firewall-cmd --add-port=8080/tcp --permanent && sudo firewall-cmd --reload   # CentOS

此时朋友已经可以用 http://服务器公网IP:8080 玩了。

⑤ 绑定域名 + HTTPS（可选但强烈建议）

装 Nginx，把域名反代到 8080。关键是 WebSocket 的 Upgrade 头必须转发，否则页面能开但联机一直失败：

server {
    listen 80;
    server_name poker.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;      # ← WebSocket 必须
        proxy_set_header Connection "upgrade";       # ← WebSocket 必须
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 600s;
    }
}

申请证书（自动改好 443 和跳转）：

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d poker.example.com
HTTPS 不会出问题：前端会根据页面协议自动把 http 换成 ws、https 换成 wss。只要页面地址和设置里填的服务器地址协议一致就行（https 页面就填 https://你的域名）。

5.2 方案 B：Windows 云主机

不想碰 Linux 就用 Windows Server：把 发布/TMH-谁是队友服务器/ 整个文件夹传上去，双击 exe，控制台里改端口/配 MySQL。记得在安全组放行 8080，并把 exe 加入「开机启动」或用 NSSM 注册成服务。

5.3 方案 C：家里宽带 + 内网穿透

没有云服务器也能让外地朋友玩，两种做法：

做法说明
路由器端口映射 在路由器「虚拟服务器 / 端口转发」里把外网 8080 转到内网这台电脑的 8080。需要公网 IP（多数家庭宽带没有，可打运营商客服申请）。
内网穿透（推荐） 用 frp / cpolar / 花生壳，把本机 8080 映射到一个公网地址。frp 客户端示例：

穿透成功后，朋友访问 http://frp.example.com:8080 即可。缺点是电脑必须一直开着、上传带宽有限（本游戏流量极小，几个人完全够）。

5.4 外网上行只有 1Mbps / 手机 APP 连不上外网服务器

先说结论：1Mbps 足够 4 个人玩。本游戏同步的是「状态快照」（谁出了什么牌、轮到谁），一手牌只有 1–2 KB，压缩后几百字节；一整局下来总共几十 KB，1Mbps（约 128 KB/s）绰绰有余。真正造成「连不上」的，通常是下面几件事。

先学会看现象

现象多半是什么怎么处理
点连接后转圈十几秒才提示超时 端口没映射 / 被防火墙丢包 / 上行被占满 检查路由器端口转发、云安全组、服务器防火墙；关掉服务器上正在跑的上传任务（网盘同步、直播、大文件下载）
立刻提示连不上 地址写错、端口没开、域名解析不到 点「测试连接」；再用手机浏览器直接打开 http://IP:端口 看能不能出页面
能连上，打着打着断开 Wi-Fi 切 4G、锁屏、路由器回收空闲连接 v1.2.4 已加心跳和「切回前台自动补连」；尽量在稳定 Wi-Fi 下打
页面能开，但一点联机就失败 Nginx 没转发 WebSocket 的 Upgrade 头 见 5.1 ⑤ 的 Nginx 配置

1Mbps 外网的正确部署姿势

  1. 换一个高位端口。不少宽带和云厂商会封 80 / 443 / 8080。改用 18080、8443、9000 之类，成功率立刻不一样。改完记得同步改端口映射 / 安全组。
  2. 别让别的程序吃掉上行。1Mbps 上行 ≈ 128 KB/s，一个网盘同步或系统更新就能占满。服务器上不要同时跑下载、直播、远程桌面传文件。
  3. 确认是不是真公网 IP。家宽很多是运营商大内网（100.64.x.x 开头），端口映射无效。这种情况用 5.3 的内网穿透（frp / cpolar / 花生壳）。
  4. 用两种网络各测一次。手机 4G/5G 能连 + 另一个 Wi-Fi 也能连，才说明公网真的可达；只有自己家的 Wi-Fi 能连，说明根本没映射出去。

v1.2.4 针对慢网做了什么

改动效果
连接超时 8s → 20s，失败自动重试 3 次慢链路握手不再被误判成「连不上」；重试期间会提示「第 2/3 次」
心跳（25 秒一次）区分「网络慢」和「真的断了」：90 秒收不到任何回包才算断线，同时防止路由器回收空闲连接
切回前台自动补连手机锁屏、回微信再回来，不用手动重连
地址智能纠正只填 1.2.3.4 自动补成 http://1.2.3.4:8080；全角冒号、结尾斜杠、ws:// 前缀都能自动修
新增「测试连接」按钮联机面板里一键验证地址，直接给出耗时和失败原因，不用靠猜
服务端 gzip + 协商缓存前端 175KB → 52KB（压缩 70%），首屏快 3 倍；二次进入只回 304（几百字节）
WebSocket 消息压缩每手牌的状态包再压掉约 60%，四个人同时在线也不挤
实测参考：1Mbps 上行、4 人同时在线，一局（约 60 手）服务器发出的总流量不到 200KB，整局只占用约 1.5 秒的上行带宽。所以慢网不会影响出牌，只会让第一次握手慢一点。

5.5 公网安全提示

  • 本游戏没有账号系统，房间码就是口令。不要用 1234 这类弱码，陌生人进房会占座。
  • 不要把 3306（MySQL）暴露到公网。
  • 长期开服建议配合 Nginx + HTTPS，并在云防火墙限制异常流量。
  • 需要重启服务时：Linux sudo systemctl restart tmh；Windows 关掉控制台窗口再打开。

9游戏规则速查

9.1 基本

  • 一副牌去掉大小王，4 人各 13 张，无底牌。
  • 点数大小：4 < 5 < 6 < 7 < 8 < 9 < 10 < J < Q < K < A < 2 < 3（3 最大）。
  • 花色大小：♦ 方块 > ♠ 黑桃 > ♥ 红桃 > ♣ 梅花（仅同点数时比）。
  • 每局抽签决定首出，开局会提示谁先出。

9.2 牌型与大小

牌型张数说明 / 大小
单张1比点数，同点比花色
对子2同点数两张，比点数、再比花色
纯 3 张3三张同点数。只能领出时打，且有严格限制（见 9.3）
顺子5五张连续，34567 最小、10JQKA 最大；2 不参与顺子
同花5五张同花色，点数任意
三带二5三张同点 + 一对
四带一5四张同点 + 一张单牌
同花顺5同花色且连续。♣34567 最小、♦10JQKA 最大

五张组合从大到小：同花顺 > 四带一 > 三带二 > 同花 > 顺子。

压制规则：只能同牌型压同牌型——单张压单张、对子压对子、纯 3 张压纯 3 张、五张组合压五张组合（五张之间再按上面的顺序比）。一直压到最大牌无人能压为止。该规则可在「设置」里改为宽松模式（允许五张压纯 3 张），默认严格。

同花怎么比：默认先逐张比点数（从大到小），点数序列相同才比花色；设置里可切换为「先比花色」（♦ > ♠ > ♥ > ♣）。

9.3 纯 3 张什么时候能打

纯 3 张（例如 444）必须在领出时打，并且只认两种情况：

  1. 本局第一次出牌：开局抽到首出权的那位玩家，第一手就能甩纯 3 张（这时手上是 13 张，也允许）。
  2. 其余 3 人都过牌、牌权回到自己，而且此刻手上正好只剩这 3 张（例如只剩 444，出完即走完）。

明确不允许：自己先打了一张大牌 → 其余 3 人全过 → 牌权回到自己 → 手上还剩一堆牌，又想甩 444。这种出法违规，游戏会拦下并提示「纯3张只能开局首出，或手上只剩这 3 张时领出」。

另外，跟牌时永远不能出纯 3 张，只能用更大的纯 3 张去压纯 3 张。

9.4 找队友（本作核心）

  • ♦A 与 ♦3 是队友标记：拿到这两张牌的人互为队友，另外两人自动结成一队。
  • 只打出一张不公开。系统不做任何标注、不提示、不回应，另一名队友自己心里知道即可。

10常见问题

Q1. 双击 exe 弹出「A JavaScript error occurred in the main process / EADDRINUSE 8080」

v1.0.1 已修复（旧版本端口被占用时会直接崩溃）。如果仍遇到，说明 8080 被别的程序占着，且不是本游戏：
① 打开服务器控制台，把端口改成 8081 再启动；客户端则会自动顺延到 8081/8082……
② 找出占用者：命令行执行 netstat -ano | findstr :8080，最后一列是 PID，再到任务管理器按 PID 结束。

Q2. 点「在浏览器打开」提示 ENOENT ... resources\index.html

v1.0.1 已修复。原因是控制台没有把前端目录指向 resources/web。现在服务器会自动在 ../web、../、../dist 中寻找 index.html。若你手工改了目录结构，请保证 index.html 在 server/ 的同级 web/ 目录里。

Q3. 电脑上能打开，手机打不开

按顺序排查：① 手机和电脑是同一个 Wi-Fi 吗；② Windows 防火墙是否放行 8080（见第 3 节命令）；③ 路由器是否开了 AP 隔离/访客网络；④ 地址是否误用了 127.0.0.1（手机上的 127.0.0.1 是手机自己）；⑤ 控制台有多条地址时，逐条试。

Q3-1. 手机 APP 填了外网地址，一直转圈然后提示「连不上」

先点地址下面的「测试连接」，它会直接告诉你结果和耗时，比反复试快得多。
· 转圈十几秒才超时 → 端口没映射、被防火墙丢包，或服务器上行被别的程序占满；
· 立刻失败 → 地址/端口写错，或域名解析不到（用手机浏览器打开 http://IP:端口 验证一下）；
· 能连但老断 → 手机锁屏或 Wi-Fi/4G 切换，v1.2.4 已加心跳和切回前台自动补连。
1Mbps 带宽不是问题：一局总流量不到 200KB，只是第一次握手慢一点。真正要查的是「端口能否从外网访问」。详细排查见 5.4 节。

Q4. 提示「房间不存在 / 房间码无效」

① 服务器重启过，房间已清空；② 房主已经退出导致房间解散；③ 大家连的不是同一台服务器（比如一个连 8080、一个连 8081）；④ 房间码输错（不区分大小写，但字母要看准）。

Q5. 页面能打开，但一点「联机对战」就提示连不上服务器

多半是 Nginx 没转发 WebSocket：检查 proxy_set_header Upgrade $http_upgrade; 和 Connection "upgrade"。另一个原因是 https 页面里填了 http:// 地址，浏览器会拦截混合内容，改成 https://。

Q6. 关闭控制台窗口后，再开客户端还是说端口被占用

v1.0.1 起关窗会正常退出并释放端口。如果你用的是旧版本，打开任务管理器结束残留的 TMH-谁是队友服务器.exe，或重启电脑。

Q7. 换台电脑双击 exe 报 Invalid file descriptor to ICU data received

这是「只把 exe 拷走了」的典型症状——Electron 客户端不是单文件程序，同目录下必须有 icudtl.dat、*.pak、locales\、resources\ 和各 dll。
解决：拷 发布\TMH-谁是队友-Windows客户端.zip 到目标电脑，右键「全部解压缩」，再双击解压出来的 exe。已经拷了文件夹但仍报错，说明复制被中断或缺文件，重新完整复制一次即可。
服务器 exe 报同样的错：v1.3.0 起服务端已改为原生窗口程序，不会再有 ICU 报错；如果还看到这个提示，说明运行的是旧版压缩包里的服务端，换成 发布\TMH-谁是队友服务器-Windows服务端.zip 即可。

Q7-1. 能不能只拷 exe 发给朋友？

不能。请发 TMH-谁是队友-Windows客户端.zip（或整个文件夹的压缩包），对方解压后再运行。

Q7-2. 在 Windows Server 2012 R2 / Windows 7 / 8.1 上双击 exe，提示「此应用无法在你的电脑上运行」

v1.3.0 起服务端已经是原生 Win32 窗口程序（Go 编译 + 内置 Node 18 运行时，完全不加载 Chromium），Win7 SP1 / 8.1 / Server 2012 R2 都能正常打开，不会再出现这个提示。
如果仍然报错，说明你运行的是客户端 TMH-谁是队友.exe——客户端是 Electron 程序，Electron 23 起放弃 Win7/8.1 内核，在这类系统上确实跑不起来。
解决：老系统上只用 发布\TMH-谁是队友服务器-Windows服务端.zip 开服，双击里面的 TMH-谁是队友服务器.exe，玩家统一用浏览器打开服务器地址进入游戏，功能完全一致。详见 第 1+ 节。

Q8. MySQL 连不上怎么办

先点「测试连接」看具体报错：ECONNREFUSED = 服务没起或端口不对；ER_ACCESS_DENIED = 账号密码/权限不对；ER_BAD_DB_ERROR = 库没建；超时 = 网络/白名单问题。修不好也不影响玩，取消「启用」即回到内存模式。

Q9. 战绩会丢吗

房间和对局状态都在内存里，服务器一重启就清空；启用了 MySQL 时，已结束的对局会写入数据库长期保留。玩家本地只记录「胜/负」场次（浏览器 localStorage）。

Q10. 人不够 4 个能玩吗

能。空位由电脑补齐，2 个人 + 2 个电脑也能开局；一个人想练牌就直接「单人练习」。

Q11. 安卓装不上 / 提示风险

允许「安装未知来源应用」；部分手机管家会把 debug 签名的 APK 标为风险，选择「继续安装」。企业分发可自行用正式证书重新签名。

Q12. 能不能改端口 / 同时开两个服

可以改端口（控制台或 server/config.json），但同一台机器上只能有一个进程占用同一个端口。想开两个独立服，用两个不同端口，例如 8080 和 8081，大家要连对应的地址。

v1.0.1 · 两处 exe 故障修复

问题原因修复
控制台点「在浏览器打开」报 ENOENT ... resources\index.html 控制台没有设置前端目录，服务器把 resources/ 当成网站根目录 启动时显式指向 resources/web；服务器自身增加多路径自动探测，找不到时返回可读的中文提示页而不是报错堆栈
两个 exe 打开就报 EADDRINUSE 0.0.0.0:8080 并崩溃 端口被占用时 server.listen() 同步抛异常，且监听错误处理器挂得太晚；另一个原因是旧版关窗后进程不退出，一直占着 8080 错误监听前置 + try/catch；控制台遇到占用会探测是否为同款服务器（是则复用、只读显示，不是则提示换端口）；客户端会自动顺延到 8081、8082……；关窗即停止服务并退出；两者都加了未捕获异常兜底，不再弹 Electron 崩溃框
控制台与客户端同时打开时行为混乱 两个程序各自抢 8080 增加 /api/status 探测：后打开的一方自动复用已有实例，界面标注「复用已有实例」
控制台关闭窗口后服务仍在后台 window-all-closed 里没有退出逻辑 关窗 → 停止服务器 → 退出进程，端口立即释放
快捷启动脚本打开浏览器过早 start 抢在服务器监听之前执行 启动服务器.bat 改为先起服务、轮询 /api/status 就绪后再打开浏览器
